# 默认输入设备启动纠偏审计 · 2026-11-08

范围：当前工作区中新增的默认麦克风固定功能，以及与其直接关联的设备选择、启动、托盘、HTTP 设置和资源释放。保留了工作区原有未提交改动。

发现并修复：

- [P1] 自动选麦直接采用系统默认通信输入。固定功能生效后，默认输入本身就是 CABLE Output；配置缺失时再次启动可能把处理后的输出采回输入。自动选择和配置设备缺失时的回退现均排除 CABLE；显式设备选择保持原语义。
- [P1] PolicyConfig 使用同一个虚表槽位调用多个不同 IID，缺乏相同接口布局保证。现在只使用已知布局的 IPolicyConfig IID；接口不可用时重试，不猜测其他接口的槽位。
- [P2] 重试次数判断在端点枚举之后，而且找不到 CABLE 时不会消耗重试预算，导致后台持续枚举。现在在任何 COM 调用之前检查完成状态、开关、暂停状态和轮询预算，失败或异常均消耗预算。
- [P2] 检查仅覆盖 Console / Communications，可能在 Multimedia 仍指向实体麦时提前宣布完成。现在核实 Console / Multimedia / Communications 三种采集角色，并在设置后再次读回确认。
- [P2] HTTP、托盘和后台线程均能直接执行切换、重置完成标记；重复发送开启也会再次纠偏。现在只有音频恢复线程执行切换；设置更新串行化，重复开启保持完成状态，只有关闭再开启才重置。
- [P2] 默认角色检查、端点枚举和 PolicyConfig 的临时 COM 对象未及时释放。新增路径使用独立枚举器并释放端点、接口指针和 COM 客户端。

最终行为：

1. `pinDefaultMic` 缺省开启；通过原有 HKCU Run 自启机制启动，仍尊重用户的开机自启选择。
2. 复用现有音频恢复线程，不新增常驻线程、计时器或设备通知订阅。
3. 未暂停时将三种 Windows 默认采集角色设置到 CABLE Output；已正确或设置后读回全部正确即结束本轮纠偏。
4. 完成后不再枚举端点或查询系统默认输入；后续设备通知、普通恢复轮询和重复发送开启均不会重新检测。用户随后主动切换默认输入也不会被抢回。
5. 未成功时前 30 次普通恢复轮询尝试纠偏，通常约一分钟；之后只在设备通知到达时再试。暂停期间不消耗预算、不切换默认输入。
6. 开关保存到配置；关闭再开启允许重新纠偏一次。
