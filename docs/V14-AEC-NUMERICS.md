# v1.4-AEC 数值稳定性修复（2026-10-25）

## 根因与证据

问题位于 LocalVQE 的 `ggml/daf_frontend.cpp` 自适应滤波器，并非模型文件损坏。

旧实现先计算 `s = mu * X2`，当 `s > 2` 时把 `mu` 乘以 `2 / s`，随后重新计算
`max(1 - 0.5 * mu * X2, 0)` 更新协方差。增益已达到上限时，这一因子理论上必须为零；
重新相乘却可能得到略小于 2 的值。在初始协方差为 1000 时，约 6e-8 的舍入残差会留下
约 6e-5 的协方差，远大于 1e-12 的下限，影响后续更新。

旧算法在同一台机器、同一模型和同一输入下，仅把 log/sqrt/exp/tanh 改为先以 double
计算再转 float，输出最大差就达到 **0.275099039**，16,000 个样本有 **13,461** 个超过
既有 `atol=1e-3, rtol=1e-2`。两次运行的延迟估计都是 0，排除了延迟切换。

原先 Windows F32 输出与历史基准的最大差为 **0.2721**，13,134 个样本超差。
上述实验能复现相同量级的分歧，证明旧算法会放大数学库的微小舍入差异。

## 修复

新增 `ggml/daf_math.h`：当 `mu * X2 >= 2` 时，直接使用 `mu = 2 / X2`，
协方差因子明确取 **0**；未限幅时使用原始乘积计算因子。保留原有模型、衰减系数、
协方差下限和测试容差。

修复后，同一数学函数对照实验的最大输出差降为 **1.257658e-5**，超差样本 **0**。
50,000 个增益/协方差样例通过 long double 公式对照；其中旧公式有 5,108 个限幅后仍残留
正因子的样例。另验证 3 秒已知回声延迟的 priming 路径。

`tests/daf_reference_math.cpp` 是舍入扰动对照，不是独立的 PyTorch 实现。

## 基准的处理

修正协方差会有意改变 v1.4 的适应轨迹，不能要求继续复现旧算法的历史输出。
四份旧 `.out.f32` 文件原样保留；新增三份 `.stable.out.f32` 和一份
`.prime.stable.out.f32`，记录修正后的输出，并由 CTest 使用。

这些新快照由修正后的 `test_regression --save` 生成；证明根因的依据是上述限幅不变量和
数学函数扰动对照，不能仅凭新快照通过就认定修复有效。旧 v1～v1.3 基准没有改变。
回归比较同时补上了 NaN/Infinity 检查，避免非有限数误判为通过。

开发专用 Zen4 native engine 的两份历史快照保持不变，尚未在相应硬件重新生成；该路径
默认关闭，不包含在本次 Windows 桌面/OBS 发行运行库中。

## 验证与边界

- 原生全量构建通过；CTest **14/14 通过，无跳过**，含 v1～v1.4 F32/BF16、前端独立版、
  priming、畸形模型拒绝和三项数值稳定性验证。
- C# **24 项**和前端 **6 项**回归通过。
- 新模型下载只用于测试，均核对源码记录的 SHA256；发行包继续只携带原有三份模型。
- 没有新增运行时线程、轮询或图形计算，修复只影响每个滤波更新的限幅公式。
- 尚未在另一操作系统复测，也没有用真实录音重新评估 ERLE、音质或长期稳定性；
  数学函数扰动测试不能替代这些验证。
